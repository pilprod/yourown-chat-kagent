# Граница интеграции kagent

## Решение

`pilprod/kagent` остаётся сопровождаемым fork и источником кода. Исправления
сначала предлагаются в upstream. Этот репозиторий хранит только интеграционный
слой: точную ревизию источника,
договор между системами и проверки поведения, необходимого K8s Agents
Platform.

Такое разделение не превращает fork-тег в продуктовый релиз и не переносит
параметры, специфичные для сервиса, в общий платформенный репозиторий.

## Разделение ответственности

| Компонент | Ответственность |
|---|---|
| Temporal workflow | долговечность AgentRun, ожидание пользователя, таймеры, повторные попытки и итоговое состояние |
| activity-адаптер `yourown-chat-agents` | перевод AgentRun в AgentInstance/A2A и сохранение серверной identity и идемпотентности |
| kagent AgentInstance service | создание и жизненный цикл конкретного экземпляра агента |
| публичный A2A-шлюз kagent | Task, история, потоковая передача, отмена и переподключение |
| Tool Gateway | политика, подтверждение, credentials и безопасное выполнение инструментов |

Temporal не повторяет внутренний цикл агента. kagent не становится источником
пользовательского состояния платформы и не заменяет долговечный workflow.

## Целевой профиль первой версии

Профиль `kap-managed-single-run-v0` использует один `AgentInstance` на один
изолированный `AgentRun`:

1. адаптер создаёт экземпляр с детерминированным `request_id`;
2. полученный `AgentInstance.id` используется как A2A `context_id`;
3. каждый A2A вызов также передаёт обязательные gRPC metadata
   `x-kagent-agent-instance-namespace` и `x-kagent-agent-instance-id`;
4. адаптер отправляет сообщение с детерминированным `message_id`;
5. после разрыва соединения адаптер повторно читает Task через публичный шлюз,
   и только сохранённая конечная Task завершает Temporal activity;
6. `input-required` переводит workflow в долговечное ожидание ввода;
7. `auth-required` использует отдельное состояние ожидания аутентификации и не
   может быть удовлетворён подтверждением действия;
8. cancel считается завершённым только после сохранённого терминального
   состояния.

`context_id` служит для корреляции, но не маршрутизации и не доказательства
полномочий. `request_id` выводится из tenant, requester, namespace и RunID.
`message_id` дополнительно включает Temporal ActivityID. Фактический ключ
kagent — `(authenticated user_id, namespace, request_id)` и действует только
пока запись AgentInstance существует: зафиксированная версия удаляет её без
tombstone. Поэтому повтор после удаления остаётся отдельным блокирующим тестом.

## Фактическое состояние версии `5229184`

| Граница | Состояние |
|---|---|
| Авторизация | `controller-v2` использует `UnsecureAuthenticator` и `NoopAuthorizer`; клиентский `x-user-id` нельзя считать доверенным |
| HITL | публичный шлюз отклоняет продолжение с `Message.TaskID`; `input-required` нельзя возобновить |
| MCP | компилятор передаёт `RemoteMCPServer.spec.url` напрямую в среду исполнения; обязательного маршрута через Tool Gateway нет |
| Восстановление потока | освобождение зависшего активного слота реализовано, но запись конечного состояния всё ещё может потеряться при отмене клиентского контекста |
| Идемпотентность после delete | tombstone отсутствует, тот же `request_id` может создать новый экземпляр |
| Артефакты | для точного commit нет утверждённого набора неизменяемых образов и чартов |

Эти пункты являются найденными возможностями для upstream issue и PR, а не
поводом создать параллельный протокол.

## Identity и авторизация

Целевой инвариант требует сохранять tenant, requester, namespace, RunID и
correlation ID на всех границах. Метаданные модели или A2A не являются
авторизацией. Полномочия должны происходить только из доверенной серверной
identity и отдельно проверяться для жизненного цикла, взаимодействия, истории
и отмены.

Зафиксированная версия этому инварианту не соответствует, поэтому её нельзя
подключать к нескольким пользователям или продуктивной среде до исправления
authn/authz и отрицательных тестов. Общий доступ (shares) не входит в первый
профиль.

## MCP и инструменты

Целевой управляемый профиль принимает только логическую ссылку на разрешённый
ресурс Tool Gateway. Прямой внешний адрес, учётные данные или значение секрета
не переходят в среду исполнения. Tool Gateway сам выбирает собственный
исполнитель либо зарегистрированный MCP-сервер.

Локальная проверка `ManagedMCPRoute` валидирует желаемый договор, но не доказывает
поведение kagent. До появления отображения CRD, admission-проверки и сетевого
deny-by-default MCP в зафиксированной версии для управляемого профиля выключен.

## Исключения первой версии

Профиль `kap-managed-single-run-v0` пока не включает shares, Shared/Dedicated
composition, checkpoint/fork, Codex/Claude Harness, browser BFF/UI и миграцию
legacy Session/SandboxAgent.

Для conformance утверждён только controller-only delta preview lane: exact fork
commit, linux/amd64 controller и неизменённый UI companion, приватные ClusterIP,
одна UI replica за отдельным Terraform-owned Cloudflare Access/Tunnel gate,
отдельный one-time CRD bootstrap и внешний Substrate `0.0.20`. Он не является
production target и не ослабляет перечисленные выше блокировки. Долгоживущий
AgentInstance на несколько AgentRun и лицензия интеграционного кода остаются
отдельными решениями.
